## C2. Exception classes, GraphQL codes and DECISIONS

## C4. Authorization matrix

Legend. **Guard** is the decorator list on the resolver method. Effective rules: `AuthGuard` = any member whose status is not REJECTED, SUSPENDED or DELETE (so USER, ACTIVE or PENDING ORGANIZER, ADMIN); `WithoutGuard` = anyone, a guest gets `authMember = null`; `RolesGuard` + `@Roles(X)` = role X, same status rule; `ActiveOrganizerGuard` additionally needs an ORGANIZER to be ACTIVE (admins pass); `ConversationGuard` = ORGANIZER or ADMIN, REJECTED and SUSPENDED allowed; `NotificationGuard` = any member, only DELETE blocked. The member is reloaded from the database on every request (#25). "Service" means an ownership or state check inside the service. Total: **97 operations (41 queries, 56 mutations), 0 subscriptions.** REST routes and the socket gateway follow the table.

- **The frontend.** `../ticketzy-next` was read only for the report format. Whether it calls `checkAuth`, `getAllMembersByAdmin` as a mutation, matches error codes, or renders AI answers as text was not checked, so renames in C3-5, C3-11, C3-12 and C3-35 need that check.

History scan covered the listed patterns in this repository only (107 commits, all refs); other secret formats and other repositories were not searched.
